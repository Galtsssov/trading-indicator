# Этап 2.3 — Feature Factory

Цель этапа — не стратегия, а полное объективное описание каждого бара (и значит каждого события).
Гипотезы H001 и H002 закрыты и не пересматриваются.

## Что построено

| Требование | Где | Как |
|---|---|---|
| 200–500 признаков | `src/qlab/factory/f_*.py` | **387 признаков в 34 категориях** (Price Structure, Liquidity, Volatility, Time, Calendar, Session, Volume, BTC / ETH / SOL Context, Relative Strength, VWAP, Order Flow Proxy, Positioning, Regime, Fractal, Candle Geometry, Statistical, Rolling Statistics, Percentiles, Z-Score, Mean Reversion, Momentum, Acceleration, Curvature, Microstructure Proxy, Entropy, Compression, Expansion, Gap, Auction, Distance Metrics, Sequence, Cluster Features) |
| Чёткое определение | поле `formula` у каждого признака | Математическая формула; функция расчёта рядом |
| Только доступная информация | тест `test_all_features_are_causal_and_finite` | Все 387 признаков считаются на полной и на обрезанной истории — значения до точки обреза обязаны совпасть |
| Независимый модуль | `family(...)` в файлах семейств | Признак = спецификация; новое семейство = новый файл, ядро не меняется |
| Тесты | `tests/test_factory.py` | Общие (причинность, конечность, полнота документации) — для каждого признака; точечные — формулы на данных с известным ответом (RSI тренда = 100, энтропия монотонного пути = 0, размерность прямой = 1, бета ряда к самому себе = 1, спред Ролла на «пиле» > 0, часы сессий с летним временем) |
| Документация | `docs/FEATURES.md` | Генерируется из кода (`python -m qlab catalog`); тест проверяет, что каталог не устарел |
| Каталог | `docs/FEATURES.md` | ID, название, формула, тип, размерность, зависимости, стоимость, предполагаемый механизм |
| Explainability | там же, таблица «Объяснение» | Для каждого признака: что реально измеряет, чем может быть полезен, ограничения |
| Корреляции и удаление дублей | `src/qlab/factory/analysis.py` | Спирмен по каждой паре монета × ТФ на training, консенсус \|ρ\|, жадное удаление \|ρ\| ≥ 0.95 (остаётся более дешёвый) |
| Кластеризация | там же | Иерархическая кластеризация по 1 − \|ρ\|: какие признаки описывают одно и то же |
| Конструктор гипотез | `engine.with_factory` | В YAML-гипотезе фильтры и событие `anomaly` могут использовать любой признак фабрики — без нового кода |

### Новая информация, а не перестановки OHLC

Часть признаков — внутрибаровые: они считаются из минутных свечей внутри 5m/15m-бара (`ib_*`):
реализованная волатильность, длина пути, частота смен направления, доля объёма в последней и самой
объёмной минуте. Этой информации в OHLCV бара нет. Также подключены метрики Binance: long/short ratio
аккаунтов и taker long/short ratio (с той же задержкой публикации, что OI).

### Как пользоваться

```bash
python -m qlab factory
```

```bash
python -m qlab catalog
```

В гипотезе (YAML) — просто имена признаков в фильтрах:

```yaml
filters: ["mo_ret_3 > 2 and of_effort_result_6 > 1", "rg_vol == 1"]
```

Стоимость: полный набор на 6 годах 5m-баров одной монеты — около минуты расчёта и ~0.8 ГБ кэша;
считается один раз и пересчитывается только при изменении данных или кода признаков.

- **Реально разных «идей» около 200, а не 387.** 339 признаков не дублируют друг друга, но при пороге
  \|ρ\| ≥ 0.7 они собираются в 207 групп. Гипотезы стоит собирать из представителей кластеров.
- **Популярные «разные» индикаторы — одно и то же.** Самый большой кластер (14 признаков) объединяет
  z-оценку к средней, удаление от VWAP, положение в диапазоне, стохастик и CCI: всё это «где цена
  относительно недавней средней». RSI(6) почти тождествен удалению от EMA12 (ρ = 0.99). Скользящий VWAP
  совпадает с положением в диапазоне (ρ = 0.96). Это подтверждает вывод этапа 1: premium/discount,
  возврат к VWAP и перекупленность — одна переменная под разными названиями.
- **Импульс = тело свечи = z-оценка доходности = перцентиль доходности** (ρ > 0.98).
- **Оценки волатильности Parkinson, Garman–Klass и Rogers–Satchell не дают ничего сверх std закрытий** (ρ 0.95–0.99).
- **Автокорреляция доходностей ≈ оценка спреда Ролла ≈ variance ratio(2)** (ρ 0.95–0.99): все три
  измеряют отскок цены между bid и ask, а не «настроение рынка».
- **Уникальная информация** — признаки-одиночки: внутрибаровые (из минуток), позиционирование
  (OI, funding, long/short), энтропия, межрыночные остатки, календарь опционов. Именно там нужно
  искать дальше, если вообще искать в этих данных.
- Вырожденный один: `mi_data_gap_minutes` (в архиве Binance почти нет дыр внутри баров).

## Хватает ли OHLCV вообще? Вывод, который можно проверить

Сомнение владельца сформулировано точно. Его можно превратить в проверяемый вывод, а не оставлять ощущением.

**1. Целевая спецификация требует большого преимущества.** «RR ≥ 1:2 и WR > 50 % после издержек» —
это ожидание ≥ +0.5R на сделку после комиссий. Всё, что платформа находила до сих пор, — это 0.01–0.13R
**до** издержек, а издержки при стопе в 1 ATR — 0.2–1.0R на 15m/5m. Разрыв — в 5–50 раз.

**2. Тест «потолка информации» (предложение для этапа 2.4).** Вместо поиска отдельных правил —
оценить верхнюю границу того, что вообще извлекается из 339 признаков:
- метка: исход сделки «+2R раньше −1R» (горизонт фиксирован, издержки учтены) на каждом баре;
- модель: градиентный бустинг на всём ядре признаков. Это не стратегия, а измерительный прибор:
  гибкая модель даёт **оптимистичную** оценку извлекаемой информации;
- обучение на training с очисткой перекрытий, оценка на validation (holdout не трогается);
- метрика под цель владельца: win rate и ожидание после издержек для 1–2 самых уверенных сигналов в
  день, против безубыточного порога (1 + издержки в R) / 3;
- контроль: та же процедура на перемешанных метках (ноль) и на подмешанном искусственном эффекте (что прибор его видит).

**Правило решения (фиксируется заранее):** если даже оптимистичный потолок на validation не дотягивает до
безубыточного WR для RR 1:2 на 5m и 15m, делается сильный вывод: *в OHLCV и производных от них признаках
на этих ТФ нет информации для заданной цели*. Поиск в этих данных прекращается, усилия переносятся в новые данные.

**3. Какие данные добавлять — по цене и ценности:**
- **aggTrades Binance — бесплатно.** Полный поток сделок со стороной агрессора: точная дельта, размер
  сделок, кластеры, скорость ленты внутри минуты. Самый дешёвый шаг вглубь.
- **Снимки стакана Binance (bookDepth) — бесплатно**, с ограниченной историей. Глубина ±1–5 %, дисбаланс.
- **Спот и Coinbase — бесплатно.** Межбиржевые различия, кто ведёт движение: спот или перп.
- **Ликвидации — бесплатно только вперёд** (запись потока). История — платно.
- **Полный L2 и тепловые карты — дорого.** Только если предыдущие шаги покажут, что микроструктура несёт информацию.
