# Этап 2.3 — Feature Factory

Цель этапа — не стратегия, а полное объективное описание каждого бара (и значит каждого события).
Гипотезы H001 и H002 закрыты и не пересматриваются.

## Что построено

| Требование | Где | Как |
|---|---|---|
| 200–500 признаков | `src/qlab/factory/f_*.py` | **387 признаков в 34 категориях** (Price Structure, Liquidity, Volatility, Time, Calendar, Session, Volume, BTC / ETH / SOL Context, Relative Strength, VWAP, Order Flow Proxy, Positioning, Regime, Fractal, Candle Geometry, Statistical, Rolling Statistics, Percentiles, Z-Score, Mean Reversion, Momentum, Acceleration, Curvature, Microstructure Proxy, Entropy, Compression, Expansion, Gap, Auction, Distance Metrics, Sequence, Cluster Features) |
| Чёткое определение | поле `formula` у каждого признака | Математическая формула; функция расчёта рядом |
| Только доступная информация | тест `test_all_features_are_causal_and_finite` | Все 387 признаков считаются на полной и на обрезанной истории — значения до точки обреза обязаны совпасть |
| Независимый модуль | `family(...)` в файлах семейств | Признак = спецификация; новое семейство = новый файл, ядро не меняется |
| Тесты | `tests/test_factory.py` | Общие (причинность, конечность, полнота документации) — для каждого признака; точечные — формулы на данных с известным ответом (RSI тренда = 100, энтропия монотонного пути = 0, размерность прямой = 1, бета ряда к самому себе = 1, спред Ролла на «пиле» > 0, часы сессий с летним временем) |
| Документация | `docs/FEATURES.md` | Генерируется из кода (`python -m qlab catalog`); тест проверяет, что каталог не устарел |
| Каталог | `docs/FEATURES.md` | ID, название, формула, тип, размерность, зависимости, стоимость, предполагаемый механизм |
| Explainability | там же, таблица «Объяснение» | Для каждого признака: что реально измеряет, чем может быть полезен, ограничения |
| Корреляции и удаление дублей | `src/qlab/factory/analysis.py` | Спирмен по каждой паре монета × ТФ на training, консенсус |ρ|, жадное удаление |ρ| ≥ 0.95 (остаётся более дешёвый) |
| Кластеризация | там же | Иерархическая кластеризация по 1 − |ρ|: какие признаки описывают одно и то же |
| Конструктор гипотез | `engine.with_factory` | В YAML-гипотезе фильтры и событие `anomaly` могут использовать любой признак фабрики — без нового кода |

### Новая информация, а не перестановки OHLC

Часть признаков — внутрибаровые: они считаются из минутных свечей внутри 5m/15m-бара (`ib_*`):
реализованная волатильность, длина пути, частота смен направления, доля объёма в последней и самой
объёмной минуте. Этой информации в OHLCV бара нет. Также подключены метрики Binance: long/short ratio
аккаунтов и taker long/short ratio (с той же задержкой публикации, что OI).

### Как пользоваться

```bash
python -m qlab factory
```

```bash
python -m qlab catalog
```

В гипотезе (YAML) — просто имена признаков в фильтрах:

```yaml
filters: ["mo_ret_3 > 2 and of_effort_result_6 > 1", "rg_vol == 1"]
```

Стоимость: полный набор на 6 годах 5m-баров одной монеты — около минуты расчёта и ~0.8 ГБ кэша;
считается один раз и пересчитывается только при изменении данных или кода признаков.
